## 企画: 追加したい機能 (新規)

---

### P1 — 低コストで効果が大きい

---

#### 1. 送信取り消し (Undo Send)

**背景**: 送信ボタンを押した直後に誤字や宛先ミスに気付くことが多いが、現在は送信後の取り消し手段がない。

**実装概要**:
- `POST /api/mail/send` を「即時送信」ではなく、サーバー側で数秒 (5〜10秒、設定可能) の遅延キューに入れる方式に変更
- `pending_sends` テーブル (Id, UserId, ConfigId, Payload(JSON), SendAt) を追加し、バックグラウンドタスクで時間経過後に実際のSMTP送信を実行
- `DELETE /api/mail/send/{id}` で送信前ならキャンセル可能
- フロントエンドは送信直後にトースト「送信しました - 取り消す」をN秒間表示し、クリックでキャンセルAPIを呼ぶ

**工数**: バックエンド中 + フロントエンド小 / 中

---

#### 2. 署名・テンプレート管理

**背景**: アカウントごとに異なる署名を自動挿入したい、よく使う文面 (定型文) を毎回書き直すのが手間。

**実装概要**:
- `user_server_configs` に `signature` (TEXT, nullable) カラムを追加し、`ServerConfigModal` で編集
- `ComposeModal` で送信元アカウント切替時に署名を本文末尾へ自動挿入 (本文末尾に区切り線 `-- ` を付与)
- 新規 `mail_templates` テーブル (Id, UserId, Title, Subject, Body) + `/api/mail-templates` CRUD を追加
- `ComposeModal` に「テンプレートを挿入」ドロップダウンを追加

**工数**: バックエンド中 + フロントエンド中 / 中

---

#### 3. ダークモード

**背景**: 夜間利用や省電力のため、UI全体のダークテーマ切り替えに対応していない。

**実装概要**:
- Tailwind の `darkMode: 'class'` 戦略を採用し、各コンポーネントに `dark:` バリアントを追加
- ヘッダーにテーマ切り替えトグル (ライト/ダーク/システム設定に従う) を追加
- 選択結果を `localStorage` に保存し、初回アクセス時は `prefers-color-scheme` を参照

**工数**: フロントエンドのみ / 中 (既存コンポーネント全体への適用工数が大きい点に注意)

---

#### 4. キーボードショートカット

**背景**: PCでの操作はマウス依存で、Gmail等に慣れたパワーユーザーには効率が悪い。

**実装概要**:
- グローバル `keydown` ハンドラを `DashboardPage` に追加
  - `j` / `k`: メール一覧の次/前を選択
  - `Enter` / `o`: 選択メールを開く
  - `c`: 新規作成 (`ComposeModal`)
  - `r` / `f`: 返信 / 転送
  - `e`: アーカイブ (アーカイブ機能実装後)
  - `/`: 検索バーへフォーカス
  - `Esc`: モーダルを閉じる
- `?` キーでショートカット一覧モーダルを表示
- 入力フィールドにフォーカス中は無効化

**工数**: フロントエンドのみ / 小〜中

---

### P2 — 受信トレイの自動化をさらに強化

---

#### 5. メールのスヌーズ (後で対応)

**背景**: 今すぐ対応できないが後で必ず見たいメールを、受信トレイから一時的に隠して指定時刻に再表示したい。

**実装概要**:
- `snoozed_mails` テーブル (Id, UserId, ConfigId, MessageUid, Folder, SnoozeUntil) を追加
- `MailDetailModal` / 一覧の各メールに「スヌーズ」ボタンを追加し、時間 (1時間後/明日/来週/カスタム) を選択
- スヌーズ中のメールは `GET /api/mail/inbox` のレスポンスから除外 (またはサイドバーの「スヌーズ中」フォルダに表示)
- `EmailCheckBackgroundService` (または新規バックグラウンドサービス) が `SnoozeUntil` を過ぎたレコードを検出し、受信トレイに復帰 + Web Push通知

**工数**: バックエンド中 + フロントエンド中 / 中

---

#### 6. 自動ラベリングルールの「アクション」拡張 (メールルール)

**背景**: 既存の自動ラベリングはラベル付与のみ。Gmailのフィルタのように「移動・既読化・削除・転送・通知ミュート」まで自動化したい。

**実装概要**:
- `auto_labeling_rules` テーブルに `action_type` (Label / MoveToFolder / MarkAsRead / Delete / Forward / Mute) と `action_value` (フォルダ名・転送先アドレスなど) カラムを追加
- `AutoLabelingService` のルール適用処理で `action_type` に応じた処理を分岐 (MailKitの `MoveToAsync` / `AddFlagsAsync` / `DeleteAsync` / `SendAsync` を呼び出し)
- `AutoLabelingRuleModal` / `RuleConditionBuilder` にアクション選択UIを追加 (既存の条件ビルダーはそのまま再利用)

**工数**: バックエンド中 + フロントエンド中 / 中〜大

---

#### 7. カレンダー招待 (.ics) 対応

**背景**: 会議招待メール (`text/calendar` パート) を受信しても、内容確認や予定登録ができず外部カレンダーアプリへの転記が必要。

**実装概要**:
- `MailController` のメール詳細取得時に `text/calendar` MIMEパートを検出し、レスポンスに `calendarEvent` (件名・開始/終了時刻・場所・主催者) を含める (ical.NETなどでパース)
- `MailDetailModal` にイベント概要カードを表示し、「カレンダーに追加」(.ics ダウンロード、または Google/Outlook カレンダーへのWeb追加リンク生成) ボタンを設置
- 出席可否 (承諾/仮承諾/辞退) ボタンから `METHOD:REPLY` の.icsを生成し、主催者へ返信メール送信

**工数**: バックエンド中 + フロントエンド中 / 中

---

### P3 — AI活用・将来拡張

---

#### 8. AIメール要約・返信案生成

**背景**: `docs/features/smart-labels-design.md` のPhase3 (外部LLM活用) で構想されている方向性を、まず「要約・返信案」機能として先行実装する。長文メールの内容を素早く把握し、返信文のドラフトを得たい。

**実装概要**:
- 新規 `AiAssistController` を追加し、`POST /api/ai/summarize` と `POST /api/ai/suggest-reply` を提供
- 外部LLM (Claude API等) をバックエンドから呼び出す。メール本文を外部送信するため **設定画面でユーザーがオプトインしない限り無効** とする (プライバシー設定をユーザー単位で保存)
- `MailDetailModal` に「要約」ボタン、`ComposeModal` (返信時) に「AI返信案を生成」ボタンを追加し、生成結果を編集可能なテキストとして挿入

**工数**: バックエンド中 (外部API連携) + フロントエンド小 / 中〜大 (プライバシー設計含む)

---

#### 9. 連絡先グループへの一斉送信 (簡易メールマージ)

**背景**: 連絡先管理機能はあるが、グループ化や複数人への個別送信ができず、BCCで代用するしかない。

**実装概要**:
- `contacts` テーブルに `group_name` (または別テーブル `contact_groups` + 中間テーブル) を追加し、`ContactsPage` でグループ管理UIを追加
- `ComposeModal` の宛先欄でグループを選択すると、グループ内の連絡先ごとに個別メールとして送信 (本文内の `{{name}}` 等のプレースホルダーを各連絡先の名前で置換)
- バックエンドの `/api/mail/send` を拡張し、`recipients[]` + `bodyTemplate` を受け取って連絡先ごとにループ送信する `POST /api/mail/send-bulk` を新設

**工数**: バックエンド中 + フロントエンド中 / 中

---

#### 10. オフラインPWA対応 (既読メールのキャッシュ閲覧)

**背景**: 通信が不安定な環境でも、直前まで見ていたメールを閲覧したい。

**実装概要**:
- Service Worker (Vite PWAプラグイン) を導入し、静的アセットをキャッシュ
- 直近閲覧した受信箱一覧・メール詳細をIndexedDBにキャッシュし、オフライン時は読み取り専用で表示 (送信・削除等の操作はオフライン時無効化)
- オンライン復帰時にキャッシュと最新データを再同期

**工数**: フロントエンドのみ / 中〜大

## 優先度まとめ

| 優先度 | 機能 | 理由 |
|---|---|---|
| 🔴 すぐ | **送信取り消し** | 実装が小さく、誤送信防止の効果が大きい |
| 🔴 すぐ | **署名・テンプレート管理** | 日常利用の手間を直接削減 |
| 🟡 近い | **キーボードショートカット** | フロントエンドのみで完結、パワーユーザー向け |
| 🟡 近い | **メールルール (アクション拡張)** | 既存の自動ラベリング基盤を活用でき投資対効果が高い |
| 🟡 近い | **スヌーズ機能** | Gmail等で標準的なUXで需要が明確 |
| 🟢 将来 | **ダークモード** | 需要は高いが既存コンポーネント全体への適用コストが大きい |
| 🟢 将来 | **カレンダー招待対応** | ニッチだが業務利用では有用 |
| 🟢 将来 | **AI要約・返信案生成** | 効果は大きいが外部API依存とプライバシー設計が必要 |
| 🟢 将来 | **連絡先グループ一斉送信** | ニッチな利用シーン向け |
| 🟢 将来 | **オフラインPWA対応** | 工数大、優先度は低め |
