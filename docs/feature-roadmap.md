## 企画: 追加したい機能

---

### P1 — メール体験の根幹を補完

---

#### 1. メール転送 (Forward)

**背景**: 返信 (Reply) はあるが転送 (Forward) がない。受信メールを第三者に送る基本操作が欠けている。

**実装概要**:
- `MailDetailModal` に転送ボタン追加
- `ComposeModal` に `initialForwardedBody` prop を追加し、引用テキスト + 添付ファイルを引き継ぐ
- バックエンド変更なし (既存の `SendMail` エンドポイントをそのまま使用)

**工数**: フロントエンドのみ / 小

---

#### 2. スレッドビュー (会話まとめ)

**背景**: 同じ件名のメールが受信一覧に個別に並び、文脈が追いにくい。Gmail的な会話形式が欲しい。

**実装概要**:
- `In-Reply-To` / `References` ヘッダーを取得してスレッドIDを生成
- `GET /api/mail/inbox` レスポンスに `threadId` と `threadCount` を追加
- 受信一覧でスレッドをグルーピング表示、クリックで展開
- DB: `mail_threads` テーブル (threadId, messageId, serverConfigId)

**工数**: バックエンド・フロントエンド両方 / 大

---

#### 3. IMAP全文検索

**背景**: 現在の検索はクライアント側フィルタのみ (表示中のメールだけが対象)。IMAPの `SEARCH` コマンドを使えばサーバー側で全メールを検索できる。

**実装概要**:
- `GET /api/mail/search?q=&configId=&folder=` エンドポイント追加
- MailKit の `inbox.SearchAsync(SearchQuery.SubjectContains("..."))` を使用
- フロントエンドの SearchBar から呼び出し、結果をリスト表示
- 検索対象: 件名・送信者・本文 (サーバー依存)

**工数**: バックエンド中 + フロントエンド小 / 中

---

#### 4. 未読バッジ・未読フィルタ

**背景**: 未読メール数がサイドバーに表示されず、どのアカウントに未読があるか一目でわからない。

**実装概要**:
- `GET /api/mail/unread-count?configId=` エンドポイント追加 (IMAPの `STATUS` コマンド)
- サイドバーのアカウント名横に未読数バッジ
- 受信一覧に「未読のみ」フィルタボタン
- `EmailCheckBackgroundService` の新着検出時にカウントを更新

**工数**: バックエンド小 + フロントエンド小 / 小〜中

---

### P2 — 生産性・UX向上

---

#### 5. メールのアーカイブ

**背景**: ゴミ箱に入れるほどではないが受信トレイから消したいメールの行き先がない。Gmailの「アーカイブ」相当。

**実装概要**:
- IMAPの `Archive` フォルダへ移動 (MailKit の `MoveToAsync`)
- `PUT /api/mail/archive/{messageId}?configId=` エンドポイント追加
- `MailDetailModal` にアーカイブボタン追加

**工数**: バックエンド小 + フロントエンド小 / 小

---

#### 6. HTMLメール作成 (リッチエディタ)

**背景**: 現在の作成はプレーンテキストのみ。HTMLメールを送る手段がない。

**実装概要**:
- `ComposeModal` に [Tiptap](https://tiptap.dev/) を組み込み (軽量・React対応)
- プレーンテキスト / HTML の切り替えタブ
- バックエンドの `SendMail` で `TextPart("html")` または `Multipart("alternative")` に対応

**工数**: フロントエンド大 + バックエンド小 / 大

---

#### 7. メール印刷 / PDF出力

**背景**: メール内容を印刷・保管したい場面への対応がゼロ。

**実装概要**:
- `MailDetailModal` に印刷ボタン追加
- `window.print()` で現在のメール本文エリアを印刷 (CSS `@media print` で不要UIを非表示)
- または `react-to-pdf` でクライアント側PDF生成

**工数**: フロントエンドのみ / 極小

---

#### 8. メール送信スケジュール (後で送る)

**背景**: 深夜に作成して翌朝9時に送りたいなどのユースケース。

**実装概要**:
- `ComposeModal` に送信日時ピッカー追加
- DB: `scheduled_mails` テーブル (configId, to, subject, body, scheduledAt, sentAt)
- バックグラウンドサービスが定期チェックして送信
- `GET /api/mail/scheduled` で一覧・キャンセル可能

**工数**: バックエンド中 + フロントエンド中 / 大

---

### P3 — セキュリティ・運用

---

#### 9. 送信メールの保存 (Sent フォルダへの自動コピー)

**背景**: 現在 `SendMail` は送信するだけで、Sent フォルダへのコピーを行っていない。一部のSMTPサーバーは自動コピーしないため送信記録が残らない。

**実装概要**:
- `SendMail` 完了後、MailKit で IMAP の `Sent` フォルダに `AppendAsync` でコピー
- `ImapFolders` テーブルの Sent フォルダパスを参照

**工数**: バックエンドのみ / 小

---

#### 10. 二段階認証メールの自動クリップボードコピー (強化)

**背景**: 現在のカスタムアクションはOTPをUIに表示するが、さらに自動コピーやAndroid通知からのワンタップコピーを実現したい。

**実装概要**:
- Web Push通知のペイロードにOTPコードを含め、通知タップで即座にコピー
- Android: FCM通知の `data` ペイロードにコードを乗せ、Tauri側でクリップボードに書き込み
- バックエンド: `AutoLabelingService` でパターンマッチした値をプッシュペイロードに追加

**工数**: バックエンド小 + モバイル中 / 中

---

#### 11. メールエクスポート (.eml / .mbox)

**背景**: バックアップや他クライアントへの移行手段がない。

**実装概要**:
- `GET /api/mail/export/{messageId}.eml?configId=` で生のMIMEメッセージを返す
- 複数選択して `.mbox` 形式でZIPダウンロード (一括エクスポート)

**工数**: バックエンド小 + フロントエンド小 / 小

## 優先度まとめ

| 優先度 | 機能 | 理由 |
|---|---|---|
| 🔴 すぐ | **未読バッジ** | 通知が来ても見落としが多い |
| 🔴 すぐ | **メール転送** | 基本機能の欠如 |
| 🔴 すぐ | **Sentフォルダ保存** | 送信記録が消える問題 |
| 🟡 近い | **IMAP全文検索** | 検索が実用レベルでない |
| 🟡 近い | **アーカイブ** | 受信トレイ整理の核心 |
| 🟡 近い | **印刷/PDF** | コスト最小・要望が明確 |
| 🟢 将来 | **スレッドビュー** | UX大幅向上だが工数大 |
| 🟢 将来 | **HTMLエディタ** | 工数大 |
| 🟢 将来 | **送信スケジュール** | 工数大・ニッチ |
